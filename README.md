# わるん会計

小規模飲食店向けの Android 日報・レシート整理アプリです。確定申告書を作るのではなく、空いた時間に売上、支出、現金残高、レシートを端末内に整理し、月末にまとめて税理士へ提出できる資料を整えるためのアプリとして実装しています。

## 技術構成

- Kotlin
- Jetpack Compose
- MVVM
- Room
- Navigation Compose
- Hilt
- Kotlin Coroutines / Flow

## 画面

タブレットでは左サイドメニューを固定表示し、右側にメイン画面を表示します。スマホでは左メニューを出さず、下部ナビとホームのメニューカードから移動します。

- ホーム
- 日報入力
- レシート
- 収支確認
- 月別整理
- 日報一覧
- 税理士向け電子提出ファイル作成と提出履歴（MyKomonへの送信は手動）
- 設定

## Compose UI方針

タブレット版とスマホ版で画面を完全に分けず、`SummaryCard`、`SalesCard`、`ExpenseCard`、`CashManagementCard`、`DailyReportForm`、`DailyReportList`、`PrimaryActionButton` などの共通Composableを使います。

端末幅によって切り替えるのは、ナビゲーション表示、カードの並び、入力フォームの列数、余白、主要ボタンの配置に限定します。

11インチ程度のタブレットでは、左側に固定サイドメニュー、右側に白ベースのカード型メインコンテンツを表示します。サマリーカードは2列中心で配置し、金額を大きく表示します。日報保存ボタンは青系の主要ボタンとして、入力フォーム下部の目立つカード内に配置します。

スマホでは左サイドメニューを表示せず、下部ナビとホームの1カラムメニューカードで移動します。カードと入力欄は縦並びにし、主要ボタンは全幅の大きなボタンとして画面下部側に配置します。

## 初回実装の範囲

- 1店舗運用
- 売上入力
- 現金、カード、QR決済、売掛の記録
- 日報内での支出カテゴリ別記録
- 日報ステータス（下書き、完了）
- 購入日ベースの仮レシート登録
- 月別整理
- 月別提出状況
- 収支確認
- Roomによる端末内保存

## 端末内保存

RoomのファイルDB（`warun-accounting.db`、schema version 16）で端末内に保存します。永続データとして、日報の `DailyReport`、支出の `ExpenseRecord`、正式証憑の `EvidenceRecord` と支出へのLink、仮レシートの `ReceiptRecord`、過去の紙提出状況の `MonthlySubmission`、電子提出履歴の `ElectronicSubmissionRecord`、アプリ設定の `AppSettings` 等を保持します。

`DailyReport` は、任意の日付、下書き/完了ステータス、記入者、売上内訳、支出カテゴリ内訳、営業開始時現金、実際の終了時現金、来客数、組数、メモ、作成・更新時刻を1件にまとめて保存します。

`ReceiptRecord` は、購入日 `purchaseDate`、撮影日相当の `capturedDate`、登録時刻 `registeredAt` を分けて保持します。購入日が不明なレシートは日付未確認として扱い、購入日を後から指定すると該当日・該当月の集計へ反映されます。

保存済みの日報と設定は `Flow` で監視して画面へ反映するため、アプリを再起動してもRoomに残っている日報一覧や集計を再表示できます。

## 初期設定

初期状態は現金商売モードです。店舗設定の「使用する決済方法」は以下の初期値です。

- 現金: ON
- クレジットカード: OFF
- QR決済: OFF
- 売掛: OFF
- その他: OFF

日報入力画面では、ONになっている決済方法だけを表示します。OFFの決済方法は保存時も0円として扱います。

簡易設定画面では、店舗名と使用する決済方法だけを設定します。事業者情報や税理士向け詳細メモは将来拡張用のデータとして残し、初期UIには表示しません。

## 日報入力

毎日必ず入力する画面ではなく、空いた時間に任意の日付で作成・編集できます。未完成の日報は下書き保存できます。

- 基本情報: 日付、記入者
- 売上: 現金売上
- 支出: 食材仕入、酒類仕入、消耗品費、水道光熱費、雑費、その他支出
- 現金管理: 営業開始時現金、現金売上、現金支出、理論上の終了時現金、実際の終了時現金、現金差額
- 営業情報: 来客数、組数、客単価、メモ

クレジットカード売上、QR決済売上、売掛売上、その他売上は、設定画面でONにした場合のみ日報入力画面に表示します。データモデル上は将来対応のため `cashSales`、`cardSales`、`qrSales`、`accountsReceivableSales`、`otherSales` を保持します。

## 収支確認

今日、昨日、今月、先月、期間指定で、売上、支出、差額、現金差額を確認できます。初期実装ではグラフは使わず、数値カード、経費カテゴリ別内訳、日別一覧で表示します。レシート支出は購入日ベースで対象期間へ集計します。

表示項目は、対象期間、売上合計、支出合計、差額、現金売上、現金支出、理論上の現金残高、実際の現金残高、現金差額、未確認レシート件数です。

## 月別整理

対象月を選び、未確認レシート、日付未確認レシート、下書き日報、過去の紙提出記録を確認します。既存の紙提出記録は削除せず、電子提出画面の過去記録として表示します。

## 税理士向け電子提出

対象月の日報Excel、支出明細Excel、保存済みEvidenceのレシートPDFをアプリの一時領域へ作成し、Androidの保存先選択または共有機能で取り出せます。Evidenceが0件の月は空のPDFを作りません。銀行明細PDFはネットバンキングから利用者がアプリ外で用意します。

完成した一時ファイルは共有先やSAF保存中の読取りを保護するため24時間保持し、共有・保存開始時に保持期限を更新します。画面終了や対象月変更では即時削除せず、次回画面準備時に期限切れのUUID世代だけを清掃します。

アプリはMyKomonへの自動ログイン、自動アップロード、API連携、認証情報保存を行いません。利用者がファイルを確認してMyKomonへ手動アップロードした後、対象月、作成日時、作成したファイル、提出日時、状態、備考を端末内へ記録します。同じ月の再作成は別の履歴として保持します。

## 日報一覧

月ごとに日報を日別一覧で表示します。各行には、日付、売上合計、支出合計、差額、現金差額、保存状態を表示します。

日付行を押すと日報詳細画面へ移動します。詳細画面から、その日付をセットした日報入力画面へ移動できます。

### 自動計算

金額は `Long` で管理し、FloatやDoubleは使いません。

- 売上合計 = 現金売上 + カード売上 + QR決済売上 + 売掛売上 + その他売上
- 支出合計 = 食材仕入 + 酒類仕入 + 消耗品費 + 水道光熱費 + 雑費 + その他支出
- 差額 = 売上合計 - 支出合計
- 理論上の終了時現金 = 営業開始時現金 + 現金売上 - 現金支出
- 現金差額 = 実際の終了時現金 - 理論上の終了時現金
- 客単価 = 売上合計 ÷ 来客数
- 来客数が0の場合、客単価は0円

### 将来のレシート撮影方針

レシート撮影は CameraX、OCRは ML Kit Text Recognition を使い、初期実装では外部AI APIを使いません。OCR結果は自動確定せず、日付、店名、合計金額、消費税、登録番号を候補として表示します。ユーザーが候補を確認・修正してから保存する流れにします。
